# dev-doc

## First invoke (required)

Ask **once**, in one shot:

1. **Where** to create the work directory (path).
2. **Which formats/features** they need among:
   - `report` (Pandoc Markdown → Typst PDF)
   - `deck` (Typst + Touying PDF)
   - `poster` / `cheatsheet`
   - `html` (report Markdown→HTML preview)
   - `docx` (Word export)
   - `latex` (article/Beamer structure export)

Then scaffold:

```bash
./scripts/scaffold.sh /path/user/named --formats=report,deck,html,docx
```

Point them at `BUILD.md` and `scripts/build.sh` / `scripts/serve-preview.sh` in that directory. **Stop loading this skill** for ordinary authoring until they ask for a pipeline task.

## Cite vs label

- Bibliography (Pandoc/DOCX): `@key` / `[@key]` with `refs.bib` (export runs citeproc).
- Office figure/table/section cross-refs: `{fig:id}` `{tbl:id}` `{sec:id}` (resolved in DOCX — do **not** use `@` for these).
- Typst PDF figure/table/section: Typst `@label` in `.typ` / `{=typst}` (bare `@name` in Markdown is always a cite).

**Escape hatch:** a hand-written `.typ` report is allowed only when Markdown cannot express the layout.

## Engines

- Typst PDF (reports, decks, posters, cheat sheets): `typst compile file.typ` or `typst watch file.typ` (REF1).
- Pandoc Markdown → Typst PDF: `pandoc report.md --standalone --pdf-engine=typst -o report.pdf` (REF4).

## Preview

```bash
./serve.sh                 # sole entry (skill root)
```

Opens `http://127.0.0.1:<port>/preview/` — HTTP root is the skill (or workdir) so `/templates/…` assets resolve. Page-faithful preview is the Typst PDF; see `references/browser.md`.
