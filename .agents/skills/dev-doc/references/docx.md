# DOCX export

Load only when the user asks for Word / DOCX.

## Quality bar

Not a bare structure dump:

| Element | Required look |
|---------|----------------|
| Data tables | Visible grid; **header row bold + background fill** (TableGrid) |
| Code | **Shaded + bordered Source Code box** with line numbers; must **not** be a multi-column data table |
| Figures / diagrams | Embedded drawings; captions **Figure N.** … |
| Tables | Captions **Table N.** … |
| Sections | Numbered (`1`, `2.1`, …) via `--number-sections` |
| Bibliography | References section via `--citeproc` + `refs.bib` |
| Lists | Bullets stay bullets; `1.` lists stay numbered |
| Cross-refs | `{fig:id}` `{tbl:id}` `{sec:id}` resolve at export (do **not** use `@` — that is citeproc) |

## Command

```bash
./scripts/export-docx.sh templates/report.md sample/report.docx
# or in a scaffolded workdir:
./scripts/build.sh docx
```

Uses `docx-scholar.lua` + `docx-rich.lua`, `--citeproc`, `--number-sections`.

Rebuild reference styles if needed: `python3 scripts/build-reference-docx.py`

## Diagrams

Typst vector diagrams are exported as PNGs under `templates/assets/` (`flow.png`, `sequence.png`, …) and referenced from Markdown so Office gets real drawings.

## Markdown patterns

```markdown
![Caption text](assets/x.png){#fig:x}
: Table caption {#tbl:y}
See {fig:x} and {tbl:y} in {sec:data}.
[@bibKey]   # bibliography cite — different from {fig:…}
```

## Viewing on macOS

**Apple Pages is fine** for viewing. If a style looks wrong, confirm in Microsoft Word or LibreOffice before treating it as a skill defect.
